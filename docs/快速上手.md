# paper-studio 快速上手（新手 3 步）

> 技能目录：`E:\DeepSeek\skills\paper-studio`（所有命令都要先 `cd /d` 到这里）
> 真源：`references/pipeline.json` —— 链路、必过门、交接契约都在那一份文件里。

## 第 0 步（新稿第一步）：生成骨架

```bat
cd /d E:\DeepSeek\skills\paper-studio
node bin/studio.cjs scaffold --out "D:\我的稿子" --name "论文名"
```

一次给你 **14 个文件**：S0–S7 阶段骨架（00-输入 → 01-检索证据 → 02-选题 → 03-大纲 → 04-数据方法 → 05-缺陷核实 → 06-正文初稿 → 07-成品件 → 09-投稿包清单）+ 现成模板（填空模板 / 一页速查 / 投稿前总检查表 / 期刊要求核实清单 / 声明四件套）。
**已存在的文件不会被覆盖**；先 `--dry-run` 可以只看计划。

## 开工前先看两样（都是真经验，不是理论）

```bat
node bin/studio.cjs lessons    :: 初稿经验库 L-1…L-12：每条带出处 + 能不能机检
node bin/studio.cjs method     :: 11 维方法论索引（选题/框架/结构/数据库/参考文献/内容/摘要/写法/降重/统计/图像完整性）
```

最该先记住的三条：**① 工作注记（⚠ / Must be confirmed）绝不能留在投出去的正文里**；**② 声明四条（含 AI 使用声明）是硬项**；**③ 先填结果、再倒着填引言与摘要**。

## 第 1 步：问「这活该怎么干」

```bat
cd /d E:\DeepSeek\skills\paper-studio
node bin/studio.cjs route "给这篇稿子做投稿前体检"
```

输出四件事：**任务类型 + 档位** · **命中关键词** · **主链路** · **必过门（带"可用/不可用"）**。

三条链路：

| 你说的话 | 类型 | 档位 |
|---|---|---|
| 投稿前 / 体检 / 过门 / 还差什么 | `check` 投稿体检 | T1 |
| 润色 / 中译英 / 语病 / 降重 | `polish` 忠实润色 | T1 |
| 写 / 起草 / 扩写 / 搭框架 | `write` 起草辅助 | **T2**（须有作者材料） |

## 第 2 步：收稿

```bat
node bin/studio.cjs intake "D:\path\你的稿子.md"
```

它会推断**文件类型与语言**（中文/英文），并按交接契约列出必填字段；缺字段会明确写 `HANDOFF_INCOMPLETE`，不会假装通过。

## 第 3 步：看清楚要过哪些门

```bat
node bin/studio.cjs gates
```

六道门（**引用 D 盘 playbook 现成脚本，不复制**）：

| 门 | 作用 |
|---|---|
| 契约门 `_contract-check.cjs` | 参考文献格式 + 强断言证据在场性 + 量化上限有无对象 |
| 引用锚点门 `_gate-claim-anchor.cjs` | claim↔reference 对齐（无锚点的引用 = HIGH 阻断） |
| 语言门 `_phrase-lint.py` | 绝对化副词 / 弱化动词 / 术语一致性 |
| 期刊契约门 `_journal-contract.cjs` | 目标刊契约（**需要 --contract JSON**；没有就跳过，不算通过） |
| 成品件核验 `_verify-docx.py` | 重开 docx 数原生对象 + 扫残留 Markdown 标记 |
| md↔docx 同步门 `_gate-artifact-sync.py` | 两份成品件是否同源同步 |

跑门：

```bat
node bin/gate-runner.cjs --task "给这篇稿子做投稿前体检" --draft 稿.md --docx 稿.docx --anchors anchors.json --manifest manifest.json
node bin/gate-runner.cjs --selftest
```

判定规则：**`rc≠0` 且 `stdout` 为空 ⇒ 前提层失败**（脚本崩了/环境缺东西，不是"结果为空"）· 缺输入 ⇒ **跳过（不算通过）** · 判据数据缺（如词库）⇒ **前提层失败，绝不因为是"空判据"就变绿**。

> **Python 门用的解释器**：优先 `D:\DeepSeek\research-paper-playbook\.venv\Scripts\python.exe`（写在 `pipeline.json` 的 `assets.python_exe`）。
> Windows 上 PATH 里的 `python`/`python3` 常常是 Microsoft Store 占位符，脚本会**跳过**它——所以看到 python 门「可用」时，用的是 venv 而不是 PATH。

## 自检（改了任何东西之后跑）

```bat
node bin/studio.cjs selftest
```

11 项，含**必失败夹具**：真源缺失必须抛错（不许返回空链路）· 无参数必须抛错（不许兜底）· 未知任务必须兜底并说明 · 门脚本缺失必须标不可用 · 缺字段必须判不完整。

## 三条纪律（每条都由一次真实事故换来）

1. **同时看退出码和 stdout**：`rc≠0 且 stdout 为空` = 前提层失败，不是"结果为空"。
2. **跑门前无条件断言解释器与脚本存在**（本机出现过子进程缺模块目录致命令不存在、把"取不到"读成零）。
3. **判据改动必须回读真值并配必失败件**（改坏必须变红，且红的是这一条）。
