# 单篇文献精读（paper-reading）

> 来源：B站《大模型无效读文献》（BV1mJ4w6HE2B，约 3 分钟）。  
> 工具：`node bin/studio.cjs reading --file <paper.md|txt|tex> [--out <工作单.md|.html>] [--json] [--strict]`

## 为什么做

直接让模型“总结这篇文献”，通常只是把摘要、引言、结论压缩一遍。读完仍然不知道：

- 它解决了什么问题；
- 为什么这个问题值得做；
- 和已有工作比，真正多做了什么；
- 方法核心是什么、最小示例怎么跑；
- 每个结论对应哪张图/哪张表；
- 在什么条件下不成立；
- 对自己当前的研究有什么可迁移的启发。

所以这个模式不追求“三分钟读完”，而是把读文献拆成 13 个必须回答的工作项，并把“作者说的 / 作者证明的 / 我认为的”分开。

## 13 个工作项

1. 研究问题
2. 动机
3. 与已有工作的差异
4. 方法核心
5. 最小示例
6. 数据与样本
7. 指标与基线
8. 主要发现
9. 证据对应
10. 边界与局限
11. 可迁移启发
12. 待追问
13. 我的判断（必须由人写）

## 工具做什么 / 不做什么

**做**：

- 从 Markdown / 文本 / LaTeX 中抽候选句，标出行号；
- 检查论文里有没有方法、结果、讨论、结论等章节；
- 生成 Markdown 或独立 HTML 工作单，每一项留“我的判断”输入框；
- `--prompt` 打印一段可直接交给任意模型的精读提示词；
- `--strict` 时，缺项会让退出码为 1（但缺项不等于论文一定没写，可能只是没用这些词）。

**不做**：

- 不调用模型，不自动生成“这篇论文的结论”；
- 不判断论文对错，不替代 `doubao-paper-close-reading` 的深度语义精读；
- 不把“抽取到候选句”当成“已经读懂”；
- 不保证覆盖 PDF 中的图、表、公式；PDF 请先转文本再喂给它。

## 纪律

- 每个“证据”必须能指到图/表/页；找不到就写“原文未说明”。
- 不许编造数字、引用、实验设置。
- “作者说的”“作者证明的”“我认为的”必须分开写。
- 工具只出工作单，最终判断由人填；这也是它和“让 AI 总结一下”最大的区别。
