# 论文插件 V3 · 规格（用户口述 + 我方设计决策）

> 本文件是**规格真源**：插件的一切行为以此为准。用户口述部分标「【用户】」，我方补充标「【设计】」。
> 建立于 2026-10-14。命名约定：**「论文方案」＝论文框架 + 方法论 + 工作流**。

---

## 0. 一句话定位

**对话内驱动、无面板、双模式（用户/开发者）、五种写作模式、专业且精简、傻瓜可用、杜绝假选择**的论文插件。
目标：**拥有市面上所有论文相关插件/技能的功能**，但比它们更清楚、更省事。

---

## 1. 形态【用户】

- **★ 不要面板（GUI）**。理由（用户原话）：面板「容易崩溃，还不好做」。
  ⇒ 移除一切面板/前端资产；**纯对话内驱动**。
- 安装后即具备两种模式，**无需用户配置**。

## 2. 双模式【用户】

| 模式 | 何时进入 | 权限 | 必须真做到 |
|---|---|---|---|
| **用户模式**（默认） | 用户在对话里调用时**直接进入** | **插件封闭**：只能**使用**，**不得更改插件自带的内容**（工作流/框架/模型/数据/脚本只读） | 对内置文件的写入必须**真的被拒**，并给出「如何进入开发者模式」的一句指引 —— 否则是**假封闭** |
| **开发者模式** | 用户说出「**进入论文插件开发者模式**」或类似意思 | **开放**：向用户**展示**工作流、框架、模型、数据、脚本，并**允许更改** | 展示要**有结构**（分类 + 路径 + 一句话说明），改完要**能自检**（改坏了要报） |

## 3. 启动与意图判断【用户】

- 触发：用户在对话里说「**启用论文插件**」「**帮我写论文**」等意思时**启动**。
- ⇒ 插件必须含一条**对用户对话的判断流程**：
  1. **意图识别**：是否在请求论文相关服务？（要能处理"帮我写论文/改论文/润色/给点意见/看看我这段"等多种说法）
  2. **不该启不启**：闲聊、其它任务**不得**被误判成论文请求（**误启与漏启都要有夹具**）。
  3. **一次一确认**：判定为论文请求后，**先确认一次**再进入模式选择（避免误启后自动开跑）。
  4. **模糊时提问**：判不准就问一句，**不猜**。

## 4. 五种写作模式【用户】—— 选项大写 + 一行小字解释 + 差异化

> 用户要求：**每个选项为大写**；**每个选项下有一行小字**解释含义与用法；**必须差异化**，用户要清楚「**为什么选它而不是另一个**」；**杜绝假选择**。
> ⇒ 下表「差异化要点」一列就是**行动差异**（不是文案差异）：它决定下一步问什么、谁做决定、产出边界在哪。

| 选项 | 小字（给用户看） | 差异化要点（**行为**不同，不是措辞不同） |
|---|---|---|
| **全代写模式** | 你只给方向与目标（+作者/邮箱/单位），其余全部由插件与联网自行完成 | **只问 4 项**（方向/目标 + 作者 + 邮箱 + 单位）然后**不再弹选项直接开写**；数据、材料、文献**全部由插件自主选择**；**明确告知：进不了实验室 ⇒ 不适合研发型/需自有实验数据的论文** |
| **共同创作模式** | 你给想法思路与作者信息；数据、图表、文献可由你提供，或由插件去找后再交你选 | **每步都有人为环节**：分步询问方向 → 数据来源（**你提供 / 插件去哪取 / 你给我我去取**）→ 图表（你给 / 我生成）→ 文献（我搜 → **你勾选**）；⇒ **可做研发型创作**（例：你在实验室得出数据交给插件写作） |
| **辅助创作模式** | 你出想法，插件给框架、思路与专业性意见，**不代写** | **不产出正文**；产出＝框架 + 思路 + 专业意见（含风险与缺口清单）；它的交付物是「**你该怎么写**」而不是「我替你写了」 |
| **润色模式** | 你给已写好的论文，插件负责润色、修改，使其更完善更专业 | **只动表达与结构，不动研究内容本身**；产出＝改后稿 + **逐处改动理由**；**不得**改动数据、结论、事实、引用对象 |
| **其他** | 不限思路，自由发挥，由当前对话的模型结合插件内容实时判断 | **不套固定流程**；由当前对话模型 + 插件素材**实时判断**怎么做；这是「**不做选择题**」的出口 |

## 5. 选项的呈现方式【用户 + 设计】

- 【用户】想要**点击式选择弹窗**（像豆包那样，用户不用手打字），并保留「**其他**」可自由填写（像问卷里固定项之外还能自己写）。
- 【设计】**先实测 DSH 对话内是否支持给用户可点击选项**（本地会话里我能用的 `ask_user_question` 正是这个能力）。
  - 若支持 ⇒ 直接用它给出 5 个选项（每个选项 = 标题 + 一行小字）。
  - 若不支持 ⇒ **退化为编号选项**：用户**回一个数字**即可（仍是"不用打字"）。
  - **不许假设**：这一条必须先实测再定（实测记录写在本文件末尾）。

## 6. 设计硬要求【用户】

1. **傻瓜式**：每一步都解释清楚；**最好每步都有选项和解释**。
2. **杜绝假选择**：选项之间必须**在行为上**不同（见 §4 差异列）。
3. **分步询问按模式差异化**：共同创作问方向/数据/文献/图表；全代写只问作者三件套后直接开写。
4. **功能对齐市面**：列出市面论文类插件/技能的**能力清单**并逐条对齐（允许联网 + Gitee/GitHub 逆向）。
5. **专业且精简**：不多余、不啰嗦；**精简 ≠ 乱减**。
6. **工程纪律**：全程查兼容性与 bug；最后整体完整性与兼容性各查一遍。
7. **成本纪律**：最专业最严格但不冗余；**不空转出一堆 bug 烧 token**。

## 7. 交付与收尾【用户】

1. 整体**完整性检查** → 收尾 → **兼容性检查**（两遍）。
2. **开源到 Gitee 与 GitHub**（新仓或原仓皆可）。
3. **在心跳网络（EigenFlux）分享**。
4. **完成后停**。

## 9. 风险与未决（先记，后实测）

1. **点击式弹窗的宿主支持**：见 §5，**必须先实测**。
2. **用户模式封闭**：需要真实拦截（`chmod`/只读目录/写前钩子），需选一种**可靠且不碍事**的实现。
3. **「功能对齐市面」的边界**：市面清单可能有需 key/付费/登录的能力（按既有用户规则：**跳过并记录**，不阻塞）。
4. **成本**：五个模式 × 完整流程 × 夹具，容易膨胀 ⇒ 优先**行为差异 + 最小夹具**。

## 10. 实测记录

- **§5 点击式选项：已定性（无需再实测宿主）** —— 本会话的工具面里**已有宿主原生能力**：
  - `ask_user_question`：`questions[{id, question, header, options:[{label, description}]}]` ⇒ **正好**能表达「选项（大写）+ 一行小字（description）」，且是**点击式、不必打字**；`multi_select` 支持多选。
  - `present`：可把文件作为交付卡片呈现（面向成品的交付用）。
  ⇒ **设计定案**：插件**不自建任何 UI**（无面板）；模式选择由**插件 SKILL.md 指示 agent 调用 `ask_user_question`**，把 5 个模式作为 `options`（label＝大写模式名，description＝一行小字）。**「其他」＝在 options 里给出「其他（自由描述）」，并允许用户直接回自由文本**（`ask_user_question` 之外的补充路径）。
  - **降级路径**（宿主若无该工具）：退化为**编号选项**（用户回一个数字）。
  - ⇒ 本项从「风险」降级为「已定案」，风险 1 关闭。
- （待填）用户模式封闭的**具体拦截方式**实测（写前钩子 / 只读目录 / 命令层守卫 三选一，需在插件里可机检）。

### 10.1 落地实测（2026-10-14）

- **§8「用户模式封闭」拦截方式：已定案并实测 = 工具层守卫（不是 chmod / 只读目录）**。
  为什么：插件要能"装任何机器都成立"，而 `chmod`/只读目录**依赖平台与安装方式**（Windows/`link:` 安装下不可靠）。
  落法：`paper_dev` 的 `write` 在封闭态**直接拒**（返回 `ok:false` + 解锁指引）；**并且**用夹具证明"目标文件内容未变"（真封闭，不是假封闭）。
- **安装方式：`link:` 规格**（`plugin_manager install_bundle target="link:E:/DeepSeek/skills/paper-studio/plugin"`）⇒ `application:applied`；装完**宿主立刻把两个工具推给会话** ⇒ 真机可用。
- **★ 真机冒烟抓到一个宿主级硬要求（mock 自检抓不到的）**：`output.presentationMeta` 返回 `{ exitCode: undefined }`（`modes` 路径没有 `exit_code`）⇒ 宿主判 **non-lossless JSON**，**整次工具调用失败**。
  落法：`presentationMeta` **只放 JSON 可表示的值**，没有就不放这个键；并**新增夹具**「`presentationMeta` / `render` / 返回值必须能无损 JSON 往返（缺键 vs undefined 视为不同）」。
- **★ 激活限制（如实记录）**：改完代码后**真机仍报同一错误**；试过 ①`set_bundle enabled=false→true` ②升版本 `3.0.0→3.0.1` 后重装（返回 `ambiguous-install`、`changed:false`）**都无效** ⇒ **`link:` 目标的代码改动需要重启 DSH 才生效**（Node ESM 模块缓存）。严重度：仅 `modes` 一条路径受影响，其余真机可用。**未擅自重启**。
- **意图判断改为可机检**：新增 `classifyIntent`（**动作词 × 对象共现**，与词序无关）+ `action=intent` + **13 条夹具**（该启 / 不该启 / 拿不准三类）。
  夹具当场抓出一个真漏判：`「这篇稿子帮我润色一下」`（倒序）原本得 `not` ⇒ 改为共现判据后正确判 `paper`；并把「只有动作词、没有对象」（如"帮我改一下"）定级为 **clarify**（规格要求：模糊就问，不猜）。
- **插件自检：`20/20`**（原 16 → 加"无损 JSON 往返"1 条 + 意图夹具 3 条）。
