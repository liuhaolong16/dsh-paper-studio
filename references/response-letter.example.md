# 返修回复信（Response to Reviewers）· 结构与模板

> 用 `node bin/studio.cjs response --letter <回复信.md> --comments <审稿意见.md>` 逐条核对。
> 机器只核三件事：**每条意见是否出现** · **回应是否实质**（不是"已修改"） · **是否指明改动位置**。回应在学术上是否站得住，仍须人读。

## 机器要求的结构（每条意见一节）

```markdown
**Comment 1:** <审稿意见原文，逐字复制（≥20 字，便于机器匹配）>

**Response:** <实质回应：做了什么、为什么这样做；**不要只写"已修改"**>
<改动位置：行号 / 页 / 节 / 图表 / "新增了…" "删去了…" —— 至少要有一处显式定位>
```

## 判定标准（可机检）

| 检查 | 通过条件 | 常见失分 |
| --- | --- | --- |
| 覆盖 | 该条意见原文（前 80 字）出现在回复信中（或 ≥40 字滑窗命中） | 漏回某条；把两条合并回一句 |
| 实质回应 | 回应正文 ≥40 字，且不是 `已修改/同意/OK/done` 这类空话 | 只写"已修改" |
| 改动位置 | 命中定位标记（`L12` / `line 12` / `p.7` / `第 3 节` / `Section 3.4` / `Fig. 2` / `Table 4` / `新增` / `删去` / `改写为`） | "我们做了修改"却不说是哪里 |

## 不同意 / 不修改时

也必须给出**理由与依据**（另需 ≥40 字，且建议引用文献或数据），并在回复里明确"未修改 + 原因"。这类条目同样要**指明位置**（例如"Keeping the original formulation in Section 2.1, because …"）。

## 复跑

```text
node bin/studio.cjs response --letter <回复信.md> --comments <审稿意见.md> [--out <报告.md>]
```
