# 论文插件 V3 · 对话驱动手册

> 这是**给模型读的操作手册**，不是给用户读的文档。用户只需要说话；选项由你用 `ask_user_question` 呈现。

## 0. 铁律（先读，再动手）

1. **不要面板**：本插件没有 GUI。所有交互都走对话 + `ask_user_question`（宿主原生可点击选项）。
2. **一次一确认**：判到论文请求后，**先确认一次**再进模式选择；**不要**判到就自动开跑。
3. **模糊时提问，不猜**：判不准就问一句「这是要写/改论文，还是在聊别的？」。
4. **杜绝假选择**：五个模式**行为不同**（见 §2 的行为差异列）。选定后**只按该模式的问题清单提问**，不要五个模式问同一套。
5. **不复制判据**：要门、体裁、预算、模板时**调 CLI 取**（`paper_studio`），不要把判据抄进回答里形成第二套说法。
6. **红线**：① 不代写**不实声明**（尤其 AI 使用声明、资助、作者贡献）；② 涉中国地图/领土/行政区划的图表，交付前做政治正确性检查、不采用国外数据源默认归属；③ 凭证永不写入档案或稿件；④ 不做规避 AI 检测类操作。

## 1. 意图判断（触发流程）

```
用户消息
  ├─ 命中论文意图（写/改/润色/审阅/投稿体检/给意见/看某段）→ 见下
  ├─ 命中「启用论文插件」等显式指令 → 直接进入 §2
  ├─ 闲聊 / 与论文无关 → **不启用**（正常回答，不要提插件）
  └─ 拿不准 → 问一句确认，再决定
```

判到论文意图后**第一步只有一件事**：用 `ask_user_question` 问「要不要启用论文插件来做这件事？」（给 是/否 两个选项）。用户选「是」才进 §2。

## 2. 五种写作模式（用 `ask_user_question` 呈现，一次问完）

调 `paper_studio` 的 `action=modes` **取权威菜单**（标签、小字、行为差异都在里面，别硬编码）。呈现规则：

- `ask_user_question`，`multi_select=false`，**5 个选项**；
- 每个选项 `label` = 模式名、`description` = 该模式那一行小字；
- 「其他」保留自由填写（用户在选项之外还能自己说）。

| 模式 | 行为差异（**决定下一步问什么、谁做决定、产出边界**） |
|---|---|
| **全代写模式** | 只问 4 项（方向/目标 + 作者 + 邮箱 + 单位）后**不再弹选项直接开写**；数据/材料/文献由插件自选；**必须提醒：进不了实验室 ⇒ 不适合研发型或需自有实验数据的论文** |
| **共同创作模式** | **每步都有人为环节**：方向 → 数据来源（你给/我去取/你给我我去取）→ 图表（你给/我生成）→ 文献（我搜 → **你勾选**） |
| **辅助创作模式** | **不产出正文**；产出＝框架 + 思路 + 专业意见（含风险与缺口清单） |
| **润色模式** | **只动表达与结构，不动研究内容**；产出＝改后稿 + **逐处改动理由**（走改动账本，缺 kind/reason 拒收）；不得改数据/结论/事实/引用对象 |
| **其他** | 不套固定流程，由当前模型 + 插件素材实时判断（「不做选择题」的出口） |

### 2.1 自动推进（内置「目标」，**宿主中立** —— 2026-10-14 用户反馈新增，2026-10-15 修正为跨宿主）

**问题（实测发生）**：长任务若没有持久目标，模型会**写几步就停**，用户得反复催「继续」——那是把编排责任推给了用户。

**★ 必须先按宿主择优**（用户 2026-10-15 指出：下载插件的人**未必用 DSH**；写死某宿主的专有 API，对别的宿主就是死指令）：

| 宿主 | 用什么当"持久目标" |
|---|---|
| DSH | `create_goal`（原生持久目标） |
| Codex | Codex 的 goals / `AGENTS.md` 任务清单；**或**本插件自带的 `paper_progress` |
| Claude Code | `TodoWrite` + 子代理；**或** `paper_progress` |
| 任何 MCP 宿主（Cursor/Cline…） | **`paper_progress`**（本插件自带，MCP 工具） |
| 没有以上任何机制 | 稿件目录里的 **`PROGRESS.md`**（纯文件，零依赖兜底） |

**规则**：用户选定模式、必要信息收齐后，**第一件事是让这件事拥有持久目标**（上表择优），此后**逐轮自动推进**：

1. **建/接续目标**：写下 objective = 「按 <模式> 把这篇论文写完并跑门交付」+ 该模式的收尾条件（用户若说「完成后停」就写进去）。
   *用 `paper_progress` 时的用法*：先 `action=read` 看有没有旧进度；没有就 `action=update` 建一份（阶段/已完成/下一步/阻塞），以后每轮 `action=append`。
2. **逐轮推进**：每轮至少落一个阶段 —— 骨架 → 检索与核实 → 协议章节（R0–R8）→ 正文各章 → 跑门 → 声明四件套 → 收尾。**每轮先读进度载体、干完追加**。**不要在阶段之间停下等用户说"继续"**。
3. **什么时候才可以停**：只有「继续」需要**用户才有的东西**（作者/单位/邮箱、选刊、是否允许某类操作）时才停；停下时**一次问清**，并**明确说其余部分我会继续做**（不要让用户以为自己不回复就全线停住）。
4. **收尾**：全部阶段完成（含跑门与声明）后：① **跑 `paper_studio action=cost`** 生成**成本总结**（token 读会话日志＝事实；金额按价格表算，表里没有的模型标「未定价」**绝不当 0**），用 `--out 交付总结.md` 落成交付物；② 把目标标记完成（原生机制则 complete；`PROGRESS.md` 则写"已完成"）；③ 给出**最终交付 + "未完成/做不到"清单**（做不到的要显形，不许静默跳过）。

`paper_studio action=modes` 的返回里有 `autonomy` 字段（`first` / `then` / `blocked` / `done` / `why` / **`hosts`** 宿主矩阵），**以它为准**；本节与它由夹具同步看守：**写死单一宿主会直接导致自检变红**。跨宿主入口见 `adapters/README.md`。

## 3. 每步都要傻瓜式

1. **每步都给选项 + 一行解释**（别只抛问题让用户猜）。
2. 提问顺序按模式走（`paper_studio action=modes` 的 `after_choice` 与各模式 `next_ask`）。
3. 需要稿件路径/期刊/体裁时，**给默认值或候选**，别让用户查。
4. 长任务给**阶段进度**（一句话），不要让用户猜跑到哪了。

## 4. 干活时怎么调工具

- **一个入口**：`paper_studio`（`action` + `args`）。常用：
  - `action=route` 判任务类型与必过门 · `gates` 列门 · `intake` 登记稿件；**`route` 还输出期刊分类路由**（该读哪份资产 + 存在性 + 边界，缺资产即失败退出）
- **合规门（v3.2.2 接线）**：`action=compliance` + `args=["<投稿包目录>"]` ⇒ 投稿前过合规与许可清单（在先发表/预印本 · 第三方许可 · 地图政治正确性 · 伦理声明 · 可机检交付）；**硬项缺一即失败，取不到即失败**；依据＝仓库 `references/compliance-checklist.md`（单一真源，工具面不复制判据）。自审三件同样可达：`action=credit`（CRediT 官方 14 角色与非官方写法核对） · `action=retract-check`（引用撤稿检查：撤稿须显式说明，取不到≠通过）· `action=claims`（文档数字一致性）· `action=hygiene`（残留件）· `action=coverage`（自检覆盖）。
  - `draft` / `scaffold` 起新稿 · `genre` 判体裁 · `sections` 出章节骨架（含篇幅预算与必答问题）
- `draft --out <目录> --form <id> --answers <答案.json> [--section <节id>]` —— **按形态起草**：任务书追加「形态级起草清单」（该形态重点/雷区 + **逐节预算**：学位论文按字、会议按页、课堂演讲按分钟）；**未收齐答案一律退 2**；不传 `--form` 时旧行为不变
- `scaffold --out <目录> --name <稿名> --form <id> --answers <答案.json>` —— **按形态出骨架**（每个形态一套：学位论文含目录/致谢/原创性声明；课堂演讲含结论先行/问答预备；开题含可行性/进度安排），并生成 `00-输入.md`（答案落盘）与 `99-自检.md`（该形态该跑哪两个门）；**答案未收齐一律退 2 且不落任何文件**；不传 `--form` 时旧用法不变
- `form list | form show <id> | form check --form <id> --draft <稿.md>` —— **论文形态**（学位论文 / 课堂演讲论文 / SCI / 开题报告 / 课程论文 / 会议论文）：**形态选流程，体裁选门**；`check` 是必备件门（缺件或无法机检一律判不合格）
- `form ask` / `form gate --answers <答案.json>` —— 启动问答：**未收齐一律退 2，不许开写**
- `form coverage` —— **七要素完整性探针**（框架/格式/方法论/核心/工作流/重点/字数）：逐形态给行，空白字段与"只有两节"都不算有，形态间 `core` 相同判不合格；**任一形态缺任一要素 ⇒ 退 2**
- `form budget --form <id> --draft <稿.md> [--minutes N] [--lang zh|en] [--answers <答案.json>]` —— **字数门 + 时间盒门**：区间按形态（**模板优先**）；课堂演讲按「分钟 × 口播速率」判**超时风险**与页数上限；**缺时长判未检查（不许猜）**
  - `verify` 跑门 · `stylecheck` 写作质量 · `polish` 润色保障（保真守卫 + 改动账本）· `revise` 审稿回复/去 AI 味/通读/缩写扩写
  - `figures` 题注与绘图建议 · `profile` 研究风格档案 · `coach` 开工教练 · `audit` 出厂审查
- **永远看退出码**：`paper_studio` 返回 `exit_code`。**0 才叫通过**；非 0 要在回答里如实说明（不要把它说成"跑过了"）。
- 需要用户提供文件时，先问路径；**不要**把稿件内容贴进对话里整篇转发。

## 5. 双模式（用户模式 / 开发者模式）

- **用户模式（默认，封闭）**：只能**使用**。`paper_dev` 的 `write` 会**真的被拒**并给出解锁指引 —— 这是设计如此，不是出错；**不要**用别的工具绕过（绕过即违背用户规格）。
- **开发者模式**：用户**明确说出**「进入论文插件开发者模式」之类的话时，先用 `paper_dev action=unlock phrase=<用户原话>` 解锁（**意图等价也放行**：含「开发者模式」即视为同一意图，回执回显识别依据；与本意图无关的话仍拒），随后 `list` / `read` / `write` 白名单资产（`references/`、`bin/`、`SKILL.md`、`plugin/**`）。
  - 展示要**有结构**：分类 + 路径 + 一句话说明（`list` 已按此返回）。
  - 改完**必须自检**：跑 `paper_studio action=audit`（出厂审查 6 项）与相关工具的自检；把读数贴出来。
  - 用完建议 `paper_dev action=seal` 收回封闭。

## 6. 与其它技能/资产的边界

| 事项 | 归谁 |
|---|---|
| 判据、门、体裁、模板、篇幅预算、教训 | **paper-studio**（`references/pipeline.json` / `templates.json`，唯一真源） |
| 起草/润色的**方法论本体** | 既有 `paper-writer` / `paper-polish` 技能（本插件只编排） |
| 论文精读 / 研究评价 | 既有 `doubao-paper-close-reading` / `doubao-academic-evaluator` |
| 本插件自己 | 对话驱动、模式选择、双模式开关、编排与桥接 |


## 8. 期刊分类（国内/国外 × 中文/外文）

开写前先定两个字段：`region`（cn/intl）与 `language`（zh/en/bilingual）——**缺一个不许开写**。

- `cn+zh` ⇒ 读 `references/cn-journals.md`（收录体系 · 平台逐字操作步骤 · 来稿体例 · 国内特有材料 · 逐刊档案）+ 该刊契约；**清单必须有「盖章/签署类材料」一栏**（三态，不许留白）。
- `intl+en` ⇒ 读 `references/submission-runbook.md` + 该刊契约；**清单必须有「系统内声明（attestation）」一栏**。
- `intl+en` 且目标刊为 **PLOS ONE** ⇒ 追加读 `references/plos-one.md`（与 Elsevier 系的差异对照表 · 图件单独 TIFF · 参考文献 Vancouver · **资助不进正文** · Cover Letter 不得提减免）。
- 参考文献按语言选标准：中文 ⇒ **GB/T 7714—2025**（前 3 人 + 等）；英文 ⇒ 刊约（多为 Vancouver，前 6 人 + et al.）。中英双投**分开生成两版**。
- 机器真源：`references/pipeline.json` 的 `journal_classes`；说明见 `references/journal-taxonomy.md`。**routing 取值必须含显式 `references/*.md` 路径**（否则 CLI 抛 `JOURNAL_ASSET_UNRESOLVED`）；CLI `route` 会把它吐出来并检查存在性。

## 本技能与 CLI 文档的关系（v3.2.90 起）

- 本文件是**对话侧技能入口**（`name: paper-studio-v3`，给技能发现器扫，从"启用论文插件 / 帮我写论文"进）；
- 根 `SKILL.md`（`name: paper-studio`）是**命令侧文档**，逐条写明全部子命令用法；
- **两者必须同时写明真源 `agent_facing` 里的每个命令** —— 插件自检有锁（跨面文档锁）会在任一份漏写时报红。

## 新增能力（v3.2.86–v3.2.88，两批吸收第三方技能包后落地）

- `talk budget --minutes 15 [--qa 3]`：**讲授预算**（内容页 ≈1 张/内容分钟、硬上限 1.25×、problem-first 分节配时；≤7 分钟自动切闪电形态）。**槽位时长必须由用户给出，绝不臆测。**
- `talk script --minutes 12 [--deck <f>]`：**口播稿预算**（按真源语速把词数摊到每页；备份页不配词）。
- `talk lint <deck.md> --minutes 12`：**幻灯片 lint**（pacing / 单页>100 词 / 要点>6 / 非断言标题 / 图片缺失 / Marp 不能渲染 PDF）。
- `reviewers aggregate <scores.json>`：**聚合评审**（置信加权均值 · champion/detractor · 拖后腿维度 · 决策风险带；含「borderline 无 champion ⇒ 向下判」）。
- `reviewers grade <transcript.md> --target 45 --max 75`：**问答演练评分**（逐答计时 / 未答 / 对冲开头 / 填充词密度 / 是否把答案埋在 yes-no 之后）。
- `review --reviews <意见.md> [--draft <稿.md>] [--budget N --unit chars|words]`：**审稿意见分诊**（严重度×成本 · 共识升级 · must/should/brief 三带 · 按回复预算分配；**分类未完成退 1**）。
- 以上 `talk` / `reviewers` / 严重度分诊的**规则与流程吸收自第三方技能包 `lifecycle-skills`（Apache-2.0）**，实现为本仓自有 Node 纯函数，**未复制其代码**；来源见 `references/external-adoptions.md`。
